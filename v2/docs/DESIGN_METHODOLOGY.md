# Design methodology

> The original checkpoint sequence below is preserved for decision history. The approved integrated strategy now uses all three directions in one product; see `INTEGRATED_REDESIGN.md`.

## Purpose of the exploration

The work is a comparison instrument, not a disguised selection. Each direction must become credible enough to lose fairly: if any candidate looks intentionally weaker, the comparison has failed.

## Shared truth, different interpretation

All candidates receive the same question, identities, evidence, refusals, commercial boundaries, and source metadata. They differ in how organizational knowledge is interpreted:

| Direction | Primary object | Visitor posture | Evidence movement | Page rhythm |
|---|---|---|---|---|
| Knowledge Observatory | Relationship in a semantic field | Investigator using an instrument | Regions activate, exclusions separate, sources converge | Spatial, continuous, scale-driven |
| Institutional OS | Claim in a working interface | Operator completing a task | Panels expose support and retrieval events | Dense, immediate, task-driven |
| Living Archive | Record in institutional history | Reader assembling a case | Records gather into a dossier and histories unfold | Editorial, episodic, materially layered |

## Semantic visual test

Every proposed visual element must answer two questions before implementation:

1. What piece of knowledge or system state does it represent?
2. What becomes harder to understand if it is removed?

Motion may represent retrieval, rank, access, lineage, temporal change, or focus. Depth may represent semantic scale or record history. Opacity may represent relevance or temporal distance. A visual that only supplies atmosphere does not pass.

## Direction gates

Before a direction is called evaluable, it must demonstrate the canonical query, all three identity outcomes, version history, restricted evidence, citation inspection, unsupported refusal, all four palettes, reduced motion, and intentional mobile composition. Work does not begin on the next direction until the current one passes this gate.

## Palette method

Palettes are semantic systems, not accent swaps. Each variant must define surfaces, hierarchy, evidence, current, restricted, superseded, relationship, focus, hover, selection, and graphics/post-processing character. Contrast is tested per variant. A shared token name does not imply shared composition.

## Evaluation method

The compare view will report measured performance, fallback status, accessibility status, and bundle contribution. Founder ratings remain subjective local inputs and are never presented as objective scores. Screenshots use matched questions and interaction states so the art directions are compared on equal evidence.

## Commercial clarity gate

Experimentation cannot conceal the offer. In every direction a business visitor must be able to understand the problem, the permission-and-evidence difference, the paid assessment, the bounded read-only pilot, human-controlled expansion, and the way to discuss a pilot without reading a long explanatory page.
